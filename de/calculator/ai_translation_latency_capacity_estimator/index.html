Kapazitätsschätzer für Latenz bei KI-Übersetzungen

Dieser Kapazitätsschätzer verbindet die gewünschte Auftragsrate einer KI-Übersetzungspipeline mit der durchschnittlichen End-to-End-Latenz. Daraus ergibt sich, wie viele Tasks im Mittel gleichzeitig in Bearbeitung sein müssen, damit das Zielvolumen ohne wachsende Warteschlange verarbeitet werden kann.

Ein zusätzlicher Puffer deckt Lastspitzen, Streuung und kurze Verzögerungen ab. Das Ergebnis ist keine direkte GPU-Anzahl, sondern ein Ziel für parallele Ausführungsslots oder Worker-Kapazität. Für Hardwareplanung muss anschließend berücksichtigt werden, wie viele parallele Tasks eine Instanz tatsächlich tragen kann.

  1. Zielrate eintragen. Nutzen Sie den gewünschten nachhaltigen Durchsatz in Tasks pro Minute.
  2. End-to-End-Latenz messen. Erfassen Sie die durchschnittliche Zeit vom Start bis zum fertigen Ergebnis.
  3. Puffer wählen. Ein höherer Puffer reduziert das Risiko, dass kurzfristige Spitzen sofort eine Queue aufbauen.
  4. Slots je Worker angeben. Tragen Sie ein, wie viele Tasks ein Worker oder eine Instanz parallel zuverlässig ausführen kann.
  5. Slots und Worker vergleichen. Der Rechner rundet die Workerzahl auf ganze Instanzen auf.
Basis-Slots = Tasks/min × Latenz(s) / 60
Slots mit Puffer = Basis-Slots × (1 + Puffer/100)
Worker = Aufrunden(Slots mit Puffer / Slots je Worker)

Die Beziehung folgt dem Zusammenhang zwischen Durchsatz, mittlerer Zeit im System und mittlerer Zahl gleichzeitig bearbeiteter Tasks. Bei stark schwankender Latenz sollte statt eines bloßen Mittelwerts ein konservativeres Szenario geprüft werden.

Was das Ergebnis bedeutet

Die Slot-Zahl ist die rechnerische Parallelität, die bei der angegebenen Rate und Latenz gleichzeitig verfügbar sein sollte.

Queueing, Batch-Verarbeitung und harte Concurrency-Limits einzelner Anbieter können zusätzlichen Puffer erfordern.

Gegeben: 180 Tasks/min, 1,8 s mittlere Latenz, 25 % Puffer und 4 Slots je Worker.

Berechnung: Basis-Slots = 180 × 1,8 / 60 = 5.40. Mit Puffer: 6.75. Worker = aufgerundet auf 2.

Ergebnis: Die Pipeline sollte mindestens 7 parallele Slots und rund 2 Worker bereitstellen.

Warum steigt die benötigte Parallelität bei höherer Latenz?

Wenn jeder Task länger im System bleibt, befinden sich bei gleicher Eingangsrate mehr Tasks gleichzeitig in Bearbeitung. Daher wächst die notwendige Parallelität proportional zur mittleren Latenz.

Soll ich p50- oder p95-Latenz verwenden?

Für eine typische Kapazität kann der Mittelwert hilfreich sein. Für strengere Serviceziele empfiehlt sich zusätzlich ein Szenario mit einem höheren Perzentil oder größerem Puffer.

Ist ein Slot gleich einer GPU?

Nein. Ein Slot bezeichnet nur einen gleichzeitig ausführbaren Task. Eine GPU oder ein Worker kann je nach Modell, Speicher und Batchgröße mehrere oder weniger als einen solchen Slot bereitstellen.

Was passiert bei 0 % Puffer?

Dann wird nur die theoretische mittlere Parallelität berechnet. Schon kleine Last- oder Latenzspitzen können dadurch zu Warteschlangen führen.

Warum wird die Workerzahl aufgerundet?

Teilinstanzen stehen in der Praxis meist nicht zur Verfügung. Deshalb muss die errechnete Kapazität auf die nächste ganze Workerzahl angehoben werden.

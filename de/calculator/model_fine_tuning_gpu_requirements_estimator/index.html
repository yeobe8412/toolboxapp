Fine-Tuning-GPU-Bedarfsschätzer

Dieser Rechner schätzt, wie viele GPUs für einen Fine-Tuning-Trainingslauf benötigt werden, um ein vorgegebenes Tokenbudget innerhalb einer Zielzeit zu verarbeiten. Eingaben sind Trainings-Tokens, nachhaltiger Trainingdurchsatz pro GPU, Skalierungseffizienz und gewünschte maximale GPU-Auslastung.

Das Modell ist bewusst linear und eignet sich für frühe Ressourcenplanung. Kommunikationsaufwand, Speichergrenzen, Datenpipeline, Checkpointing und nichtlineare Skalierung können den tatsächlichen Bedarf erhöhen.

  1. Tokenbudget übernehmen
    Verwenden Sie die geschätzte gesamte Trainings-Tokenmenge über alle Epochen.
  2. Zieldauer festlegen
    Geben Sie an, in wie vielen Stunden der Lauf abgeschlossen sein soll.
  3. Einzel-GPU-Durchsatz messen
    Tragen Sie einen nachhaltigen Trainingsdurchsatz für Modell, Präzision und Sequenzlänge ein.
  4. Skalierungseffizienz berücksichtigen
    Mehrere GPUs skalieren selten perfekt linear; der Effizienzwert reduziert die nutzbare Leistung.
  5. Auslastungsreserve setzen
    Eine zusätzliche Auslastungsgrenze kann Reserve für System- und Datenpipeline-Overhead abbilden.
  6. GPU-Anzahl aufrunden
    Der errechnete Bedarf wird auf die nächste ganze GPU aufgerundet.

Was das Ergebnis bedeutet

Die Hauptzahl ist die kleinste ganze GPU-Anzahl, die im linearen Modell die Zieldauer erreichen kann.

VRAM-Anforderungen können eine Mindestanzahl oder einen bestimmten Parallelisierungsansatz erzwingen, unabhängig vom reinen Durchsatz.

Gegeben: 132 Mio. Tokens, 8 h, 7.000 Token/s pro GPU, 85 % Skalierungseffizienz, 90 % Auslastung.

Berechnung: R = 132.000.000 / 28.800 = 4.583,33 Token/s. Effektiv je GPU = 7.000 × 0,85 × 0,90 = 5.355 Token/s. Bedarf = 0,86.

Ergebnis: 1 GPU im Durchsatzmodell; Speicheranforderungen sind separat zu prüfen.

Was ist Skalierungseffizienz?

Sie beschreibt, welcher Anteil einer ideal linearen Mehr-GPU-Skalierung tatsächlich erreicht wird. Kommunikation und Synchronisation senken diesen Wert häufig.

Soll ich Peak- oder Durchschnittsdurchsatz verwenden?

Für Planung ist ein nachhaltiger Durchschnittswert aus einem repräsentativen Trainingslauf besser geeignet als ein kurzzeitiger Peak.

Warum kann VRAM wichtiger sein als der Durchsatz?

Ein Modell, Optimizer-Zustände, Aktivierungen und Batchdaten müssen in den verfügbaren Speicher passen oder über mehrere GPUs verteilt werden. Dann kann die GPU-Mindestzahl höher sein als die reine Durchsatzrechnung.

Wie wirkt eine kürzere Zieldauer?

Der erforderliche Gesamtdurchsatz steigt umgekehrt proportional zur verfügbaren Zeit. Halbiert sich die Zieldauer, verdoppelt sich im linearen Modell der erforderliche Durchsatz.

Sind Datenladen und Checkpoints enthalten?

Nur indirekt, wenn Ihre Auslastungs- oder Effizienzannahmen diese Overheads bereits widerspiegeln. Für detaillierte Planung sollten sie separat gemessen werden.

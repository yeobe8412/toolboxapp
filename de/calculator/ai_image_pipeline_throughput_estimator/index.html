Durchsatzrechner für KI-Bildpipelines

Der Durchsatzrechner für KI-Bildpipelines schätzt, wie viele Bild-Tasks eine GPU-Flotte pro Stunde verarbeiten kann. Entscheidend sind die Anzahl verfügbarer GPUs, die gemessene GPU-Zeit je Task und der Anteil der Zeit, der tatsächlich produktiv genutzt wird.

Damit lässt sich prüfen, ob eine bestehende Flotte ein Zielvolumen schafft oder wie sich Optimierungen der Laufzeit auswirken. Der Rechner modelliert GPU-Rechenzeit; Engpässe durch CPU, Speicher, Queueing oder Datenübertragung können den realen Durchsatz zusätzlich begrenzen.

  1. GPU-Anzahl eintragen. Zählen Sie nur Geräte, die der Pipeline tatsächlich zur Verfügung stehen.
  2. GPU-Zeit pro Task messen. Verwenden Sie die effektive Zeit unter der geplanten Konfiguration.
  3. Nutzbare Auslastung angeben. Idle-Zeit, Scheduling und sonstiger Overhead reduzieren den theoretischen Maximalwert.
  4. Betriebsstunden wählen. Damit wird zusätzlich der Tagesdurchsatz berechnet.
  5. Ergebnis mit Nachfrage vergleichen. Liegt die Zielrate höher, müssen Laufzeit, Auslastung oder Flottengröße angepasst werden.
Tasks/h = GPUs × 3600 × (Auslastung/100) / GPU-Sekunden je Task
Tasks/Tag = Tasks/h × Betriebsstunden

Die Formel setzt voraus, dass der gemessene GPU-Zeitwert den realen durchschnittlichen Rechenbedarf abbildet. Wenn mehrere Tasks gleichzeitig auf einer GPU laufen, sollte der Wert aus Messungen dieses Betriebsmodus stammen.

Was das Ergebnis bedeutet

Der Hauptwert zeigt den nachhaltigen modellierten Durchsatz der gesamten GPU-Flotte in Tasks pro Stunde.

Kapazitätsgrenzen anderer Pipeline-Stufen können den End-to-End-Durchsatz unter diesen Wert drücken.

Gegeben: 8 GPUs, 10 GPU-s/Task, 78 % nutzbare Auslastung und 24 Betriebsstunden.

Berechnung: Je GPU = 3.600 × 0,78 / 10 = 280,8 Tasks/h. Gesamt = 8 × 280,8 = 2.246,4 Tasks/h. Pro Tag = 53.913,6 Tasks.

Ergebnis: Rund 2.246 Tasks/h beziehungsweise 53.914 Tasks/Tag.

Warum liegt der reale Durchsatz oft unter dem theoretischen Wert?

I/O, Modellwechsel, Queueing, CPU-Vorverarbeitung oder ungleichmäßige Laufzeiten können zusätzliche Engpässe erzeugen. Die Auslastung sollte diese Effekte soweit möglich aus Messdaten abbilden.

Kann ich 100 % Auslastung eintragen?

Ja, mathematisch ist das möglich. Für dauerhaften Produktionsbetrieb ist 100 % jedoch meist ein theoretischer Grenzwert ohne Puffer.

Wie berücksichtige ich mehrere Bildgrößen?

Verwenden Sie einen gewichteten mittleren GPU-Zeitwert oder rechnen Sie getrennte Szenarien je Auflösung. Ein einzelner Durchschnitt kann Spitzenlasten verdecken.

Warum werden GPU-Sekunden statt Latenz verwendet?

Latenz kann Warte- und Nicht-GPU-Zeit enthalten. Für GPU-Durchsatz ist der tatsächlich verbrauchte GPU-Zeitanteil die passendere Größe.

Kann ich daraus direkt die benötigte GPU-Zahl ableiten?

Ja, indem Sie die Formel nach GPUs umstellen. Der separate GPU-Bedarfsrechner berücksichtigt zusätzlich eine explizite Kapazitätsreserve.

CNC Machine Cycle Time Estimator

Estimate the average time required for one completed unit on a cnc machine using observed productive run time and output. The result turns a batch-level observation into a per-unit cycle time, which makes it easier to compare actual pace across runs or against takt time. Production engineers and supervisors can use the result to identify pace changes, support line balancing, or establish a realistic baseline before investigating downtime and quality losses separately. Because this is an average, it can hide variation between individual cycles, changeovers, product variants, and brief interruptions.

Average cycle time (minutes/unit) = Productive run time ÷ Completed units

Average output rate (units/hour) = Completed units ÷ Productive run time × 60

Projected units per reference shift = Reference shift minutes ÷ Average cycle time

The calculation uses average observed pace and assumes that pace continues across the reference shift for the projection.

What the result means

The main result is the average productive minutes required per completed unit during the run you entered.

Use separate downtime, OEE, or yield analysis when you need to explain why the observed cycle differs from an engineered standard.

Given: 255 productive minutes, 85 completed units, and a 480-minute reference shift.

Calculation: Cycle time = 255 ÷ 85 = 3.000 minutes/unit. Output rate = 85 ÷ 255 × 60 = 20.00 units/hour. Projected shift output = 480 ÷ 3.000 ≈ 160 units.

Result: Average cycle time = 3.000 minutes per unit.

Interpretation: At the observed productive pace, each completed unit consumes about 180.0 seconds of run time on average.

Is cnc machine cycle time the same as takt time?

No. Cycle time describes the observed or expected production pace per unit, while takt time is the maximum average pace needed to satisfy demand with the available production time.

Should downtime be included in productive run time?

For this average productive-cycle model, exclude periods when the process is not producing the counted units. Use an OEE or availability analysis when downtime needs to be reflected explicitly.

Can I use good units only?

Yes, if your goal is good-output cycle time, but apply that definition consistently. If you count all completed units including rejects, the metric describes gross production pace instead.

Why does projected shift output differ from actual shift output?

The projection assumes the observed pace continues through the entire reference shift. Breaks, changeovers, downtime, product mix, and quality losses can reduce actual output.

What sample size should I use?

Use enough cycles to represent normal operating conditions. A very short run may be overly sensitive to temporary speed changes or unusual work content.

Planificador de presupuesto de latencia de red

Este planificador ayuda a repartir un objetivo de latencia entre los componentes de una ruta de red. Suma retrasos de acceso, transporte, procesamiento, seguridad y colas, y compara el total previsto con un límite que tú defines. La salida principal indica cuánto margen queda antes de alcanzar ese objetivo o cuánto se ha excedido.

Es útil al diseñar aplicaciones interactivas, voz, escritorios remotos, sistemas distribuidos o enlaces entre sedes. No sustituye mediciones de RTT ni modela automáticamente jitter o pérdida: funciona como un presupuesto de ingeniería en el que cada entrada debe representar una estimación coherente, idealmente de latencia en un solo sentido.

1. Fija el objetivo
Define la latencia máxima aceptable para el caso de uso y mantén el mismo criterio de medida en todas las entradas.

2. Estima la última milla
Incluye el acceso del usuario o dispositivo hasta el primer punto de agregación relevante.

3. Añade el transporte
Introduce el retraso esperado por la WAN, Internet o enlaces entre sedes.

4. Suma procesamiento y seguridad
Considera firewalls, proxies, cifrado, inspección u otros elementos que añadan retardo.

5. Reserva colas y variación
Añade una cifra para colas o jitter si quieres evitar consumir todo el objetivo con valores nominales.

6. Evalúa el margen
Un resultado positivo indica margen disponible; uno negativo señala que el presupuesto excede el objetivo.

Margen = Objetivo − (Acceso + Transporte + Procesamiento + Seguridad + Colas)

Objetivo: latencia máxima admisible, en ms

Cada componente: retardo estimado del tramo o función, en ms

Supuestos: Todas las cifras deben representar la misma dirección de medida. No mezcles RTT con latencia unidireccional sin convertirlas.

Qué significa el resultado

Un margen de 25 ms permite asignar hasta 25 ms adicionales antes de alcanzar el objetivo.

Si el margen es negativo, revisa los componentes dominantes o eleva el objetivo solo si el servicio puede tolerarlo.

Datos:

  • Objetivo: 100 ms
  • Acceso: 15 ms
  • Transporte: 35 ms
  • Procesamiento: 8 ms
  • Seguridad: 5 ms
  • Colas: 12 ms

Cálculo:
Latencia usada = 15 + 35 + 8 + 5 + 12 = 75 ms. Margen = 100 − 75 = 25 ms.

Resultado: 25 ms de margen

Interpretación: Se ha consumido el 75 % del objetivo y queda una cuarta parte del presupuesto por asignar.

¿Debo introducir latencia de ida y vuelta o de un solo sentido?

El planificador funciona con cualquiera de los dos enfoques si todas las cifras siguen el mismo criterio. Para presupuestos por tramo suele ser más claro usar latencia unidireccional.

¿Dónde incluyo el jitter?

Puedes reservarlo en la entrada de colas y margen de jitter. Si tu aplicación usa un búfer específico, también puedes reflejar ahí una estimación conservadora del retardo añadido.

¿Qué ocurre si el margen sale negativo?

Significa que la suma de componentes supera el objetivo. El valor absoluto indica cuántos milisegundos deberías recortar o cuánto tendría que cambiar el objetivo.

¿La pérdida de paquetes forma parte de la latencia?

No directamente. La pérdida puede provocar retransmisiones y aumentar tiempos efectivos, pero este modelo no calcula esa dinámica; conviene evaluarla por separado.

¿Puedo usar valores medios?

Puedes, aunque para servicios sensibles suele ser más útil presupuestar percentiles altos o cifras conservadoras. Un promedio puede ocultar episodios breves que degradan la experiencia.
